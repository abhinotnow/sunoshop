\section{1. Track 1: SunoShop (Use Case 2 -- eCommerce) \ -- \ Problem Statement \& Understanding}
Standard AI assistants assume users can see, hear, type, and read English. Modern eCommerce breaks this across two critical dimensions:
\begin{itemize}\setlength{\itemsep}{0.2pt}\setlength{\topsep}{0.2pt}\setlength{\leftmargin}{1.1em}
  \item \textbf{Input Gap:} Blind and motor-impaired individuals cannot parse dense DOMs, hidden controls, or drag-and-drop sliders (WCAG 2.5.7). Screen readers force them to listen to hundreds of unlabelled elements in an exhaustive linear stream.
  \item \textbf{Output Gap:} Assistants emit lengthy visual descriptions and hallucinate product specifications, while translation corrupts brand names and prices into phonetic gibberish. Users remain unprotected from dark patterns like hidden cart fees.
  \item \textbf{Target Conditions:} Visual (Mandatory / blind-first), Ageing, and Hand-motor, with zero reliance on specialized hardware.
\end{itemize}

\vspace{-2pt}
\section{2. Idea}
SunoShop is a web application acting as an accessible voice-first shopping proxy built on a \textit{ground-then-speak} paradigm:
\begin{itemize}\setlength{\itemsep}{0.2pt}\setlength{\topsep}{0.2pt}\setlength{\leftmargin}{1.1em}
  \item Speaks only facts verified within an offline-cached Product Knowledge Object (PKO), strictly separating unstructured reviews from factual specs.
  \item Asserts ``the specs state'' only for confirmed attributes, actively blocks checkout dark patterns, and communicates via Bhashini Indic models.
  \item Confines operations strictly to shopping assistance, deliberately excluding ungrounded medical or financial advice.
\end{itemize}

\vspace{-2pt}
\section{3. Approach and Architecture}
Computation is tiered: repetitive tasks run offline on-device; cloud calls are reserved strictly for grounded reasoning.
\begin{enumerate}\setlength{\itemsep}{0.1pt}\setlength{\topsep}{0.1pt}\setlength{\parsep}{0pt}\setlength{\leftmargin}{1.1em}
  \item \textbf{Offline Ingestion:} Catalogs are normalized into PKO JSONs. Gemini Flash Vision pre-computes image descriptions, and OCR structures size charts offline to eliminate live-vision latency.
  \item \textbf{Triggering:} Voice activity detection (VAD) captures speech hands-free, with a massive push-to-talk button as an alternative.
  \item \textbf{Fast-Path Routing \& Entity Masking (Rule-Based):} Intercepts simple commands (\textit{repeat, slower, simpler}). Brand names, prices, and numbers are masked with tokens prior to translation to prevent transliteration errors.
  \item \textbf{Translation Pipeline:} Bhashini ASR transcribes voice to text, translated to English pivot text ($\le 50$ words).
  \item \textbf{Grounded Reasoning:} Gemini Flash-Lite retrieves chunked reviews via aspect cosine-similarity (RAG) and exact specs via direct PKO lookup.
  \item \textbf{Deterministic Verification:} A finite state machine (not an LLM) controls checkout, enforcing explicit spoken confirmation while stripping hidden fees.
  \item \textbf{Synthesis \& Accessible Rendering:} Chained Bhashini Translation+TTS restores unmasked entities. Outputs spatial audio via Web Audio API alongside synchronized on-screen captions.
\end{enumerate}

\vspace{-2pt}
\section{4. Planned Testing}
\textbf{Test Set:} 30--40 real products in PKO format in Telugu, Hindi, English, covering complex size charts, code-mixed reviews, and 15 planted prompt-injection reviews. \quad
\textbf{Metrics:} Time-to-information; words listened; hallucination rate (0\%); prompt-injection bypasses (0); false-accept rate on checkout confirmation; brand/spec translation preservation. \quad
\textbf{Baselines:} Raw eCommerce DOM via NVDA/TalkBack; plain LLM responses through Bhashini TTS. \quad
\textbf{Validation:} 3--5 participants across five shopping tasks (including blindfolded teammates and native TalkBack/NVDA users). \quad
\textbf{Boundaries:} Cached catalog snapshot, simulated checkout, heuristic condition inference.

\section{1. Track 2: Oriel (Use Case 3 -- City Signage) \ -- \ Problem Statement \& Understanding}
Physical city streets amplify assistive failures across visual and linguistic boundaries:
\begin{itemize}\setlength{\itemsep}{0.2pt}\setlength{\topsep}{0.2pt}\setlength{\leftmargin}{1.1em}
  \item \textbf{Input Gap:} Blind and motor-impaired individuals must aim cameras at unseen targets and tap tiny buttons; 51.6\% of photos taken by blind users exhibit critical quality flaws, predominantly framing and motion blur (VizWiz, CVPR 2020).
  \item \textbf{Output Gap:} Multimodal models emit ungrounded visual descriptions and struggle with small, stylized, or glared street text and Indian scripts (NetraLink, ICVGIP 2025). Street signs frequently mix Telugu, Hindi, and English, where a single misidentified route number misdirects the user.
  \item \textbf{Target Conditions:} Visual (Mandatory / blind-first), Ageing, and Hand-motor, with zero reliance on specialized hardware.
\end{itemize}

\vspace{-2pt}
\section{2. Idea}
Oriel is a zero-tap web application reading city signs aloud based on an active \textit{verify-then-guide} paradigm:
\begin{itemize}\setlength{\itemsep}{0.2pt}\setlength{\topsep}{0.2pt}\setlength{\leftmargin}{1.1em}
  \item Speaks only facts verified across multiple sharp frames (route, destination, platform, arrow), marking unconfirmed text as uncertain.
  \item Actively coaches aiming when a critical fact is obscured: \textit{``I can read Secunderabad but not the route number. Hold still, zooming in.''}
  \item Asserts ``the sign says'' strictly for confirmed text via Bhashini Indian language models, restricting scope to sign reading (no ungrounded route planning).
\end{itemize}

\vspace{-2pt}
\section{3. Approach and Architecture}
Repetitive filtering executes locally on-device; cloud pipelines are engaged only for sharp, validated text frames.
\begin{enumerate}\setlength{\itemsep}{0.1pt}\setlength{\topsep}{0.1pt}\setlength{\parsep}{0pt}\setlength{\leftmargin}{1.1em}
  \item \textbf{Continuous Monitoring (On-Device):} Streams low-resolution camera frames, tilt, and motion sensors; optional MediaPipe head tracking.
  \item \textbf{Triggering:} Auto-captures upon steady, text-bearing frames; hands-free voice command (``read''); head dwell; or a single massive button.
  \item \textbf{Quality Gate \& Active Guidance (Rule-Based):} Detects invalid tilt (facing ground/sky), blur, darkness, or glare. Spoken guidance runs in bounded 5-second sweeps (\textit{``Slowly turn left, I'll say stop''}); caps at 3 attempts before honest abstention.
  \item \textbf{High-Resolution Burst:} Captures a 1-second burst, selects the 3 sharpest frames, and crops around text to defeat hand tremors.
  \item \textbf{Multimodal Reading:} Gemini Flash-Lite parses structured JSON per frame (type, script, route, destination, arrows); validated against PaddleOCR.
  \item \textbf{Multi-Frame Verification:} A field is confirmed only when 2 of 3 frames agree and Unicode script is valid; otherwise triggers re-read or abstains.
  \item \textbf{Speech Synthesis \& Rendering:} Feeds condition-tailored views. Chained Bhashini Translation+TTS locks route numbers and place names against transliteration corruption; provides synchronized on-screen captions and a two-way speech relay (``Ask someone nearby'').
\end{enumerate}

\vspace{-2pt}
\section{4. Planned Testing}
\textbf{Test Set:} 30--40 real signs photographed in Hyderabad in Telugu, Hindi, and English (bus stops, metro, street, shops), spanning clear, blurry, far, cut-off, and glare conditions with 2--3 frames per sign and ground truth labels. \quad
\textbf{Metrics:} Detection rate; key-fact accuracy; \textbf{wrong-but-confident rate} (headline safety metric); correct abstention rate; time-to-key-fact; taps per reading (target: 0); bad-aim recovery rate; route/place name translation preservation; end-to-end latency. \quad
\textbf{Baselines:} Plain LLM response read via Bhashini TTS; single-frame baseline; generic ``try again'' feedback. \quad
\textbf{Validation:} 3--5 participants across five sign tasks (including blindfolded teammates and simulated motor constraints); live outdoor bus stop testing. \quad
\textbf{Boundaries:} Stationary use only (no dynamic route planning), reduced aiming dependency, mobile data dependency.
